# 开单流程状态（PSSTATUS）

定义在 `genesis_backend/common/constants.py` 的 `PSSTATUS` 元组中。

## 状态编码

| 编码 | 含义       | 说明                               |
|------|------------|------------------------------------|
| 10   | 开单       | 刚新建的挂单/开单，尚未到店        |
| 20   | 客户到店   | 客户已到店，可以开始服务           |
| 30   | 配料完成   | 服务所需配料/产品已准备完成        |
| 40   | 服务完成   | 服务/操作已完成                    |
| 50   | 可以结账   | 服务完成，可进行结账               |
| 60   | 下次结账   | 本次不结账，下次再结（挂账继续）   |
| 70   | 已结账     | 已结账完成，流程结束               |

## 关键规则

- `psstatus_hung` 挂单时存入 `ExpvstollHung.psstatus_hung` 字段
- 新开单默认值 = `'10'`
- `CAN_CHECKOUT_FLAG = '70'` 表示已结账
- 未结账筛选：`psstatus_hung__in=['10','20','30','40','50','60']`
- 结账时更新为 `'70'`（见 `cashier/views.py`）

## 与预约状态的区别

预约状态（`BookingEvent.bookingstatus`）使用 100-390 编码段，表示客户预约的流程节点；
开单状态（`PSSTATUS`）使用 10-70 编码段，表示门店服务开单的流程节点。
两者通过 `ExpvstollHung.bookingeventid` 关联。
